## Final review fix wave — 2026-08-15

The final review findings were implemented and rerun on the same macOS arm64 host:

- Serial opens now use one canonical fail-closed resolver over persisted ID, transport, inclusive
  identity-quality threshold, and required capability. Endpoints do not disambiguate; duplicate
  persisted identities return `runtime.resource.ambiguous`.
- Failed or cancelled opens roll back only their provisional generation reservation. A 4,096-entry
  invalid-selector stress test retained zero generation identities, while exposed generations
  remained monotonic across failed reopen and cancellation.
- Wire v1 now negotiates inclusive minor ranges through additive fields, selects the highest shared
  minor, preserves legacy exact-minor defaults, and uses
  `runtime.protocol.version_incompatible` for no overlap.
- Both Windows broker entry points create first and subsequent Named Pipe instances with a protected
  DACL granting access only to the current user, LocalSystem, and built-in Administrators. The
  warnings-denied Windows cross-target lint passed; native DACL inspection remains pending.
- The Python Windows transport now gives steady-state pywin32 handle ownership to one bounded actor
  thread in nonblocking byte mode. Mocked blocked-read/write cancellation proves close waits for
  ownership return; native `PIPE_NOWAIT` acceptance remains pending.
- `HalError` decision-only serde round-trips, startup-token equality is available only through the
  explicit constant-time API, every v1 envelope payload tag is locked, structured connection and
  cleanup errors are logged without diagnostics/secrets, and Unix cleanup guards are armed

## Final scoped residual correction — 2026-08-15

The Windows Python transport now handles pywin32 311's direct-`Exception` native error type across
connect, read, and write. In steady state, only `ERROR_NO_DATA` (`232`) is retryable; zero-byte
writes are treated as polled, cancellable backpressure, while other native statuses terminate the
actor and close the handle exactly once. The platform-neutral model intentionally uses an exception
that does not inherit `OSError`, matching pywin32 311's public hierarchy.

Implementation and tests were completed before one unified verification run, matching the current
repository workflow. The canonical Rust gates, 119-test Python suite, generated-protocol check, and
warnings-denied Windows cross-target lint passed on the macOS arm64 host. Native Windows pywin32
execution remains an external acceptance gate.
