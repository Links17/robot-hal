# v0.3.0 USB/GPIO acceptance evidence

**Date:** 2026-08-17 (Asia/Shanghai)  
**Implementation branch:** `feat/v0.3-usb-gpio`  
**Host:** macOS arm64; Rust 1.85.1; Python binding suite under uv  
**HEAD before release-documentation changes:** `956a263415b3160a59d310d796d244cd42617d46`

## Delivered scope

- Platform-neutral USB Control/Bulk/Interrupt and GPIO line/edge contracts.
- Per-claim USB and per-line-group GPIO bounded runtime workers, lease fencing, owner cleanup,
  finite close deadlines, and quarantine when non-cancellable native work misses that deadline.
- Wire major 1, inclusive minors `0..=2`; minor 2 adds USB/GPIO requests, responses, sessions,
  capabilities, and validated conversions without changing existing tags.
- Broker dispatch, Rust and Python session clients, and virtual USB/GPIO adapters used by
  hardware-free black-box conformance.
- Opt-in native `nusb`, Linux `libgpiod`, and Windows WinRT GPIO adapter crates.

## Bound review

| Surface | Bound and overflow behavior |
| --- | --- |
| USB transfer payload | At most 16 KiB; invalid values fail before adapter dispatch. |
| USB pending transfers | At most 64; full admission returns `runtime.queue.full`. |
| GPIO edge request | At most 1,024 events; zero or oversized capacity is invalid. |
| GPIO edge delivery | Default capacity 256; oldest events are dropped and structured lag is reported. |
| Native blocking work | Runs in terminal workers rather than Tokio executor workers; a close deadline quarantines a worker that does not exit. |
| Broker connection | 1 MiB frame cap, 32 request admission/execution, 64 response queue, and 64 event retention as documented in the architecture. |

## Incomplete release gates

The canonical `cargo fmt --all --check` and workspace clippy gate passed before the full workspace
test command. The full `cargo test --workspace --all-features` gate did not complete: it reproducibly
hangs in the existing CAN test
`seeed-hal-runtime/tests/can_runtime.rs::management_pressure_does_not_starve_receive_deadline`
after more than 60 seconds. Running that test alone also hangs. This is a release blocker; this
document does not claim a passing full Rust workspace gate.

Linux cross-target validation for `seeed-hal-adapter-linux-gpio` is environment-blocked on this
macOS host because `libgpiod-sys` requires a Linux sysroot plus cross-aware `pkg-config`
(`PKG_CONFIG_SYSROOT_DIR`). This is not evidence of native Linux execution.

## External hardware qualification gates

- Native USB interface claim and Control/Bulk/Interrupt behavior:
  [`nusb-native.md`](../runbooks/nusb-native.md).
- Linux GPIO read/write and monotonic rising/falling edge qualification:

- Windows GPIO controller read/write and close/reopen qualification:
  [`windows-gpio-native.md`](../runbooks/windows-gpio-native.md). Windows does not claim

All native hardware tests are ignored by default. No native device, GPIO controller, or external
hardware gate was run for this evidence.
