**Date:** 2026-08-18 (Asia/Shanghai)

## Delivered scope

- Platform-neutral Camera discovery, exact NV12/YUYV/MJPEG format negotiation, exclusive capture
  sessions, lifecycle fencing, capability-gated controls, and bounded frame metadata.
- A broker-owned named shared-memory ring for frame payloads: four to eight slots, latest-wins
  backpressure, pin validation, drop counting, validated identity/token/layout, and no frame bytes
  in protobuf IPC.
- Wire major 1 minor 3 Camera control-plane additions, broker dispatch, Rust client validation, and
  Python Camera value/client contracts.
- Deterministic virtual Camera conformance plus target-native AVFoundation, V4L2, and Media
  Foundation adapters. Native adapter availability is target-scoped and no adapter fabricates
  controls or unsupported formats.
- A virtual-broker black-box flow that negotiates minor 3 and validates Camera enumerate, exclusive
  open, capture, shared-memory descriptor, frame lease, drop count, controls, close/reopen, and
  stale-generation rejection.

## Bound review

| Surface | Bound and overflow behavior |
| --- | --- |
| Camera dimensions | At most 4096 × 2160; invalid requests fail before adapter publication. |
| Frame payload | At most 24 MiB; format-specific planes, overlaps, arithmetic, and payload ranges validate before Ready publication. |
| Shared-memory ring | Four slots by default and four through eight permitted; free slot first, otherwise oldest unpinned Ready slot; no writable slot drops the incoming frame. |
| Frame borrowing | One pin per session/client; next acquire releases its previous pin; close invalidates mapping access and stale lease generations fail closed. |
| Native-to-ring payload | At most one copy from native buffer to broker-owned slot; copier failure or over-report restores the slot state. |
| Camera worker | Commands are bounded; native blocking work uses owned workers; timeout teardown quarantines the native claim until the worker exits. |
| Broker frame protocol | Control envelopes retain the 1 MiB cap; frame payloads are never placed in protobuf messages. |

## Cross-target and hardware limits

- The Media Foundation Windows GNU target check validates Rust/binding type paths but does not
  exercise a Windows runtime, privacy consent, driver, or camera.
- Linux V4L2 target checking remains blocked on this macOS host because `v4l2-sys-mit` requires
  Linux kernel header `linux/videodev2.h`; this is neither Linux execution nor V4L2 qualification.
- AVFoundation compiled and its hardware-free tests ran on macOS, but no authorized selected camera
  was supplied, so its physical test remained ignored.
