# USB and GPIO v0.3 design

## Scope

v0.3 adds two independent, platform-neutral hardware classes without adding product or device
protocol semantics. USB supports device discovery, interface claiming, and bounded Control, Bulk,
and Interrupt transfers. GPIO supports line discovery, configuration, reads, writes, and bounded
edge-event streams with monotonic timestamps. Isochronous USB remains out of scope for Camera v0.4;
PWM, waveform generation, and USB-to-GPIO device protocols remain out of scope.

## Architecture

New `seeed-hal-usb` and `seeed-hal-gpio` crates define typed public interfaces and capability
constructors. The runtime owns per-resource workers, queues, leases, cancellation, and cleanup just
as it does for Serial and CAN. USB and GPIO session state remains separate: a USB interface claim
cannot be represented as a GPIO lease, and a GPIO event stream cannot share USB transfer queues.

`seeed-hal-testkit` supplies deterministic virtual USB and GPIO adapters. They are the conformance
baseline and are used by broker black-box tests. Production adapters are `nusb` on macOS/Linux/
Windows, `libgpiod` on Linux, and WinRT GPIO on Windows. macOS GPIO advertises no native adapter;
attempted access fails closed with a structured unsupported-capability error. No adapter interprets
the protocol of a USB GPIO bridge.

## Interfaces and bounds

USB descriptors retain physical identity separately from the transient bus/address endpoint. A
session claims one interface and exposes Control, Bulk, and Interrupt operations. Every request has
an explicit timeout, a bounded payload, and a bounded pending-transfer queue; cancellation releases
the claim or terminally retires an uninterruptible native worker.

GPIO configuration includes direction, active-low, and adapter-supported bias/drive values. A line
session permits reads and writes according to direction. Edge subscriptions select rising, falling,
or both edges and use a bounded queue with documented oldest-drop plus a structured lag indication.
Events include a monotonic timestamp and sequence; wall-clock time is never inferred.

## Broker compatibility

Wire major remains 1. USB and GPIO messages, envelope tags, enums, and capabilities are additive in
wire minor 2. Clients negotiated below minor 2 reject USB/GPIO entry points locally; brokers reject
minor-0/1 USB/GPIO envelopes before runtime dispatch. Rust and Python clients expose protobuf-
independent types and preserve the existing request correlation, owner cleanup, and bounded writer
rules.

## Errors and lifecycle

Ambiguous identity, unavailable native APIs, unsupported configuration, stale generations, queue
overflow, and incompatible protocol minors fail closed using stable names/categories. Broker
sessions retain native handles; clients receive opaque session IDs and lease generations only.
Closing a GPIO event subscription or USB session stops new work, drains or cancels bounded work as
documented, and releases platform resources. HAL does not impose domain-safe output states.

## Verification and qualification

Each hardware class has public contract tests, virtual-adapter conformance, runtime ownership tests,
wire tag locks, Rust/Python client tests, and broker black-box coverage. Default verification is
hardware-free. Linux `libgpiod`, Windows WinRT, native USB devices, hotplug, and physical GPIO edge
tests are explicitly documented external qualification gates. CI compiles relevant target paths;
physical tests remain ignored.

## Acceptance criteria

v0.3 is complete only when both virtual adapters pass shared conformance; broker minor-2 negotiation
and owner cleanup pass black-box tests; all queues and payload limits are bounded; generated protocol
bindings are reproducible; and acceptance evidence distinguishes local results from native hardware
qualification.
