# CAN/CAN FD v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a complete raw CAN/CAN FD vertical slice with virtual conformance, Linux SocketCAN, Windows/Linux PCAN-Basic, local broker support, and Rust/Python clients.

**Architecture:** Seeed HAL owns stable CAN types and behavior while adapter-private bridges reuse `can-hal-rs`, `can-hal-socketcan`, and `can-hal-pcan`. A typed runtime `CanManager` owns one worker per physical channel, multiplexes bounded Observe/Control sessions, and reserves exclusive Maintenance sessions for configuration. Wire major 1 gains additive minor 1 request/response messages; ordinary CAN data uses bounded protobuf batches rather than unsolicited events or shared memory.

**Tech Stack:** Rust 2024/MSRV 1.85, Tokio, prost/protobuf, Python 3.11, `can-hal-rs 0.4.2`, `can-hal-socketcan 0.4.2`, `can-hal-pcan 0.4.2`, SocketCAN netlink APIs, PCAN-Basic dynamic loading.

**Spec:** `docs/superpowers/specs/2026-08-16-can-v0.2-design.md`

## Global Constraints

- Raw Classical CAN/CAN FD only; do not add ISO-TP, J1939, CANopen, UDS, DBC, or product/device-protocol concepts.
- Do not add gRPC, HTTP, remote transport, scheduled transmission, or clock synchronization.
- Seeed HAL public APIs and protobuf-independent Python APIs must not expose third-party CAN crate types.
- Pin the initial adapter dependencies to the approved `0.4.2` line and keep them adapter-private.
- Broker/crate release version becomes `0.2.0`; wire stays major 1 and supports minor range `0..=1`.
- Wire changes are additive; never change or reuse existing protobuf tags or enum values.
- `Attach` never changes link configuration. `Configure` requires an exclusive Maintenance lease and restores persistent platform state on close.
- One physical channel has one owned worker. No blocking driver or netlink call runs on a Tokio executor worker.
- RX rings default to 256 frames and drop oldest with `can.receive.lagged`; TX capacity defaults to 64 frames and rejects an entire new admission with retryable `runtime.queue.full`.
- Filters are session-local, at most 64 per session, atomically replaced, and software-authoritative.
- Single receive/send batches contain at most 64 frames.
- Every queue is bounded. Every timeout/cancellation/cleanup path is finite.
- Every error after canonical resolution carries `resource_id`; raw OS and documented PCAN statuses use `platform_code` and `vendor_code` respectively.
- Do not log hardware serials, topology paths, vendor IDs, raw frames, or diagnostic details by default.
- Do not create USB, GPIO, Camera, Node, or unrelated placeholder modules.
- Write focused contract and regression tests during Tasks 1–11, but do not run tests, lint, builds, cross-checks, or formatting checks. Task 12 is the single unified verification gate. Protocol generation in Task 5 is an implementation step and is allowed before Task 12.


Bitrates must be nonzero; sample point is `1..=999` permill; SJW is nonzero. Classic Configure rejects data timing; FD Configure requires data timing. `CanFilterSet::new` rejects the 65th filter and invalid ID/mask widths. Empty means receive all. Implement `matches(&CanFrame)` with exact Standard/Extended and class behavior.

A filter with all three class flags false is invalid. For data/remote frames, matching applies ID, mask, format, and class. For error frames, any filter with `error = true` matches regardless of that filter's ID/mask/format because error frames have no portable arbitration ID.

- [ ] **Step 5: Define adapter and channel seams**

```rust

pub trait CanAdapter: Send + Sync {
    fn adapter_name(&self) -> &'static str;
    async fn enumerate(&self) -> HalResult<Vec<ResourceDescriptor>>;
    async fn open(

pub trait CanChannel: Send {
    fn descriptor(&self) -> &ResourceDescriptor;
    fn active_config(&self) -> &CanActiveConfig;

}
```

`CanBusState` is `Active | Warning | Passive | BusOff | Stopped | Unknown`; `CanBusStatus` carries optional TX/RX counters. `CanActiveConfig` contains the queried effective link configuration and a fresh clock-domain ID.

### Task 3: Implement CAN lease compatibility and fencing

- Produces: `CanLeaseTable` reservation/commit/release/validate behavior used only by `CanManager` in Task 4.

- [ ] **Step 1: Define provisional reservation state**

Track per resource: last exposed generation, a map of internal pending reservations keyed by session ID, zero or more active Observe leases, optional active Control lease, and optional pending/active Maintenance lease. `reserve` returns an internal reservation identity and mode but no public `LeaseToken`. `commit(reservation)` increments the last exposed generation and returns the public `LeaseToken`. Failed/cancelled reservations never consume a generation; exposed generations never decrease or repeat.

- [ ] **Step 2: Implement exact compatibility rules**

- Observe may coexist with Observe and one Control.
- Control may coexist with Observe but not another Control or Maintenance.
- Maintenance requires no other active or provisional lease.
- New Observe/Control is rejected while Maintenance is active or provisional.
- New Maintenance is rejected while any Observe/Control is active or provisional.

Return `runtime.lease.conflict` with canonical resource ID. `validate` checks resource, session, owner, full token equality, mode permission, and active exposure. An older Observe generation remains valid while its exact lease is active; opening a newer compatible Observe or Control lease does not stale it. Released generations are never valid or reused.
