# Seeed HAL v0.1 Core and Serial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working cross-platform v0.1 vertical slice with platform-neutral core types, a library-first Serial runtime, a conformance adapter, a real Serial adapter, a local broker, and Rust/Python clients.

**Architecture:** Hardware-class interfaces are typed and separate. `seeed-hal-runtime` owns identity resolution, sessions, bounded queues, leases, fencing generations, and cleanup; `seeed-hal-broker` exposes those same semantics over length-delimited protobuf on Unix domain sockets or Windows Named Pipes. No product or device-protocol concept enters the workspace.

**Tech Stack:** Rust 2024/MSRV 1.85, Tokio, async-trait, bytes, serde, thiserror, uuid, prost, tokio-util, serialport, tokio-serial, tracing; Python 3.11+, protobuf, pytest, pytest-asyncio, pywin32 on Windows.

**Spec:** `docs/architecture/hal-architecture.md`

## Global Constraints

- The responsibility seam in `docs/contracts/hal-responsibility.md` is normative.
- The implementation is library-first; broker and in-process calls use the same runtime implementation.
- v0.1 contains Serial only. Do not create empty CAN, USB, GPIO, or Camera crates.
- Core, runtime, protocol, broker, and client crates forbid unsafe code.
- No blocking hardware call runs on a Tokio executor worker.
- Every queue is bounded and has a tested overflow result.
- Persisted identity and current endpoint remain distinct.
- Every lease operation validates its fencing generation.
- Protobuf changes are additive and field numbers are never reused.
- Default tests require no physical hardware.
- Hardware-dependent tests use the `hardware-tests` feature and are excluded from default CI.
- Use Conventional Commits and commit after every task.

```rust
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct SerialConfig {
    pub baud_rate: u32,
    pub data_bits: DataBits,
    pub parity: Parity,
    pub stop_bits: StopBits,
    pub flow_control: FlowControl,
    pub read_timeout: std::time::Duration,
}

#[async_trait::async_trait]
pub trait SerialAdapter: Send + Sync {
    fn adapter_name(&self) -> &'static str;
    async fn enumerate(&self) -> HalResult<Vec<ResourceDescriptor>>;
    async fn open(
        &self,
        selector: &ResourceSelector,
        config: SerialConfig,
    ) -> HalResult<Box<dyn SerialSession>>;
}

#[async_trait::async_trait]
pub trait SerialSession: Send {
    fn descriptor(&self) -> &ResourceDescriptor;
    async fn read(&mut self, max_bytes: usize) -> HalResult<bytes::Bytes>;
    async fn write_all(&mut self, bytes: &[u8]) -> HalResult<()>;
    async fn flush(&mut self) -> HalResult<()>;
    async fn set_control_lines(&mut self, lines: ControlLines) -> HalResult<()>;
    async fn close(&mut self) -> HalResult<()>;
}
```

`read(0)` returns an invalid-argument error. `close()` is idempotent. Any operation after close returns `runtime.session.closed`.

```rust
impl HalClient {
```

```python
class FramedTransport(Protocol):

        raise NotImplementedError
```

Production Unix and Windows classes implement all three methods and enforce the 1 MiB frame limit.
