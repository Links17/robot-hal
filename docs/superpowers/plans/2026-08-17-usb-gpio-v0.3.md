# USB and GPIO v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver platform-neutral USB Control/Bulk/Interrupt and GPIO line/edge-event APIs through the library, broker, Rust/Python clients, virtual adapters, and supported native adapters.

**Architecture:** Add separate `seeed-hal-usb` and `seeed-hal-gpio` crates. Extend the existing runtime ownership pattern with independent USB interface and GPIO line actors, then expose additive wire-minor-2 operations through the existing broker connection and clients. Native adapters register independently; macOS GPIO fails closed when no adapter is available.

**Tech Stack:** Rust 2024/MSRV 1.85, Tokio, Prost, nusb, libgpiod, WinRT GPIO, Python 3.11/uv.

**Spec:** `docs/superpowers/specs/2026-08-17-usb-gpio-v0.3-design.md`

## Global Constraints

- HAL remains transport/hardware-class only: no USB device protocol, GPIO product workflow, or safety logic.
- Every queue and transfer/event payload has an explicit bound and overflow contract.
- All lease tokens carry monotonic fencing generations; ambiguous identity and unsupported capability fail closed.
- No blocking native operation runs on a Tokio worker; platform calls use native async or an owned blocking worker.
- USB is Control/Bulk/Interrupt only; isochronous and PWM are out of scope.
- GPIO supports input/output/configuration/rising-falling-both edges and monotonic timestamps.
- Wire v1 minor 2 is additive; existing fields/tags are never reused.

### Current implementation boundary

- The wire contract can enumerate and open USB/GPIO resources at negotiated minor 2, but no
  operation can yet be made through a broker-owned USB/GPIO session.
- Runtime owner revocation is implemented, but manager execution is not yet the bounded
  actor/worker model required by this plan.
- No Rust client, Python client, native adapter, native hardware qualification, or release
  verification may be described as implemented for v0.3.

## Planned file structure

- `crates/seeed-hal-usb/{src/lib.rs,src/adapter.rs,src/transfer.rs,tests/usb_contract.rs}`: USB public API and bounds.
- `crates/seeed-hal-gpio/{src/lib.rs,src/adapter.rs,src/line.rs,tests/gpio_contract.rs}`: GPIO public API and event model.
- `crates/seeed-hal-runtime/src/{usb_manager.rs,gpio_manager.rs}`: independent actor/lease lifecycle.
- `crates/seeed-hal-testkit/src/{virtual_usb.rs,virtual_gpio.rs}`: deterministic conformance adapters.
- `adapters/{nusb,linux-gpio,windows-gpio}/`: native adapter crates.
- `proto/seeed/hal/v1/hal.proto` and protocol conversion/tests: minor-2 wire contract.
- broker/client/Python files: IPC dispatch and public client surfaces.
